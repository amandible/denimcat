# Detour Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Implement Detour, a new 2-4 player card-placement-and-pawn-chase game, as a full engine/server/client package on the denimcat platform.

**Architecture:** Follows the standard per-game package shape every other game here uses (`packages/engine-detour`, `packages/server/src/games/detour`, `packages/client/src/games/detour`) — see `docs/adding-a-new-game.md` for the conventions this plan applies. The engine is pure/stateless (no I/O); the server wires it to `RoomStore` via the `GameModule` contract; the client is a thin socket-driven view.

**Tech Stack:** TypeScript, Vitest (engine + server tests), React (client), Socket.io — matching every existing game.

**Spec:** `docs/superpowers/specs/2026-10-28-detour-design.md` (approved) and its source, `design/detour/rules.md`.

## Global Constraints

- Public game (Alison's own design) — lives in `packages/`, not the private submodule.
- Board: 5 columns × 4 rows minus the top-right and bottom-left cells — 18 cells, fixed regardless of player count.
- Player decks: 4 fixed arrow rotations of `[up, left, right, down]`, one step further rotated per deck (A/B/C/D) — see `decks.ts` in Task 1.
- Which deck(s) are in play is randomized per game, not tied to seat order.
- A card is played onto a cell whose current top value is strictly lower than the played card's value, and which is not the pawn's current cell. A card with no such legal target anywhere becomes wild (playable on any non-pawn cell regardless of value).
- The pawn moves one space per the just-played card's arrow from its own current position; landing on the active player's own card scores a point and continues the chain using that card's arrow; the chain stops on a non-owned card, an off-board attempt, or an attempt to re-enter a cell already visited this same chain (none of these three stop conditions score an extra point, but points already scored earlier in the same chain stand).
- Final score per player = chain points accumulated all game + 1 per that player's cards currently on top of a stack once every hand is empty. Ties are a shared win (platform convention).

## Review Focus

- **A hand with no legal normal target for any card** (e.g. three high-value cards once the board has mostly been covered with even-higher values): must never stall — the wild fallback (Task 3) makes every card playable on some non-pawn cell. A test must exercise a hand where every card relies on the wild fallback, not just the normal path.
- **Chain re-entering a 2-cycle** (two of the active player's own cards with arrows pointing at each other): must stop instead of looping forever (Task 4) — this is the exact scenario a design review surfaced; a dedicated test is required, not just trusted from the design doc's prose.
- **A move off the board from a cell adjacent to one of the two missing corners** (not just a generic edge): the two removed cells (top-right, bottom-left) create asymmetric neighbors — a cell that's a normal edge in one board orientation might be a corner-adjacent case in Detour specifically. Task 1's adjacency tests must cover every edge cell individually, not just "the board has edges" in the abstract.
- **End-of-game timing in a 2-3 player game**: the game must end only once *every seated player's* hand and deck are both empty, not when the first player to finish does — Task 5's tests must include an asymmetric case (not all players reaching empty on the literal same global turn count, since turn order interleaving means "turn 20" for one seat lands on a different absolute turn index than "turn 20" for another).
- **A tie for highest final score**: must produce a shared win (every tied seat in `winner`), matching the platform convention stated in the design doc — Task 5 needs an explicit tie test, since the design doc states this as "left to the builder" rather than spelled out in the rules.

Default `seats: ['p1', 'p2']`, each `players[seat]` defaulting to `{ deckId: 'A' or 'B' respectively, hand: [], deck: [], score: 0 }` (vary the default `deckId` per seat so a test that forgets to override it still gets two distinct decks), `activeSeat: 'p1'`, `phase: 'playing'`, `winner: null`, `log: []`. **Use real `CellId` strings (`"row-col"`, Task 1's format) in every cell-keyed override throughout every later task's tests — never placeholder letters.**

### Task 4: Pawn movement and chain resolution

**Files:**
- Create: `packages/engine-detour/src/movement.ts`
- Test: `packages/engine-detour/test/movement.test.ts`

**Interfaces:**
- Consumes: `GameState`, `cellInDirection` (Task 1); `directionFor` (Task 1); `makeState` (Task 2).
- Produces: `resolveChain(state: GameState, seat: SeatId, firstDirection: Direction): { pawnCell: CellId; pointsScored: number }` — does not mutate `state`; the caller (Task 5's `engine.ts`) applies the returned `pawnCell`/score itself. Starting from `state.pawnCell`, steps one cell in `firstDirection`; if that's off-board, returns immediately with the unchanged `pawnCell` and `pointsScored: 0`. Otherwise, loops: if the new cell is owned by `seat`, increments `pointsScored`, records the cell as visited-this-chain, and continues using `directionFor(state.players[seat].deckId, state.cells[newCell].value)`; if the new cell is not owned by `seat` (neutral or another seat), stops there (that cell becomes the final `pawnCell`, no extra point for it). Before taking each step, if the next cell would be off-board OR would be a cell already visited earlier in this same call, stop immediately without moving there (final `pawnCell` is wherever the pawn already was).

```typescript
import { describe, expect, it } from 'vitest';
import { resolveChain } from '../src/movement';
import { makeState } from './helpers';

describe('resolveChain', () => {
  it('moves one cell with no chain when the landing cell is not the active player\'s', () => {
    const state = makeState({
      pawnCell: '1-1',
      cells: { '0-1': { value: 3, owner: 'neutral' } },
    });
    const result = resolveChain(state, 'p1', 'up');
    expect(result).toEqual({ pawnCell: '0-1', pointsScored: 0 });
  });

  it('scores a point and keeps chaining across the active player\'s own cards', () => {
    const state = makeState({
      pawnCell: '2-1',
      players: { p1: { deckId: 'A' } }, // card value 1 -> up (deck A)
      cells: {
        '1-1': { value: 1, owner: 'p1' }, // first landing: p1's own, arrow up (card 1)
        '0-1': { value: 5, owner: 'neutral' }, // chain lands here next, stops (not p1's)
      },
    });
    const result = resolveChain(state, 'p1', 'up');
    expect(result).toEqual({ pawnCell: '0-1', pointsScored: 1 });
  });

  it('stops without moving when the first step would leave the board, scoring nothing', () => {
    const state = makeState({ pawnCell: '0-0' });
    const result = resolveChain(state, 'p1', 'up');
    expect(result).toEqual({ pawnCell: '0-0', pointsScored: 0 });
  });

  it('a chain may legally return to the pawn\'s OWN starting cell (not "visited" until actually moved onto this turn), scoring once and then stopping there since that cell is neutral by default', () => {
    // p1 owns '1-1' only; its deck-A value-4 direction is 'down', pointing
    // straight back at the pawn's own starting cell '2-1'. The starting
    // cell was never "moved onto this turn" (the pawn was already sitting
    // there before the turn began), so returning to it is NOT blocked by
    // the repeat-visit rule — it's a fresh landing. '2-1' itself is left at
    // its default-helper neutral value (never overridden to 'p1' here), so
    // the chain stops there without a second point.
    const state = makeState({
      pawnCell: '2-1',
      players: { p1: { deckId: 'A' } },
      cells: {
        '1-1': { value: 4, owner: 'p1' }, // deck A, value 4 -> down
      },
    });
    const result = resolveChain(state, 'p1', 'up');
    // 2-1 -> 1-1 (owned by p1, +1 point; visited={'1-1'}) -> direction
    // becomes down (card value 4) -> 1-1 -> 2-1: '2-1' is NOT in visited
    // (only '1-1' is), so this is allowed; '2-1' is neutral (never
    // overridden), so the chain stops there with no second point.
    expect(result).toEqual({ pawnCell: '2-1', pointsScored: 1 });
  });

  it('stops a true mid-chain loop (A -> B -> A) without re-scoring A, keeping the first point', () => {
    const state = makeState({
      pawnCell: '2-1',
      players: { p1: { deckId: 'A' } },
      cells: {
        '1-1': { value: 1, owner: 'p1' }, // deck A, value 1 -> up (toward '0-1')
        '0-1': { value: 4, owner: 'p1' }, // deck A, value 4 -> down (back toward '1-1')
      },
    });
    const result = resolveChain(state, 'p1', 'up');
    // 2-1 -> 1-1 (+1, visited {1-1}) -> 0-1 (+1, visited {1-1,0-1}) -> would
    // re-enter 1-1 (already visited this chain) -> stop at 0-1.
    expect(result).toEqual({ pawnCell: '0-1', pointsScored: 2 });
  });
});
```

**Interfaces:**
- Consumes: everything from Tasks 1-4 (`cellInDirection`, `directionFor`, `isLegalPlacement`, `resolveChain`, `GameState`, `pushLog`, `cloneState`).
- Produces: `ok<T>(state: GameState, data?: T): EngineResult<T>`, `err<T>(code: string, message: string): EngineResult<T>` (copy `packages/engine-mint-condition/src/result.ts`'s shape exactly); `isGameOver(state: GameState): boolean` (every seat's `hand` and `deck` both empty); `computeFinalScores(state: GameState): Record<SeatId, number>` (each seat's `score` plus 1 per `BOARD_CELLS` cell currently owned by that seat); `determineWinners(scores: Record<SeatId, number>): SeatId[]` (every seat tied for the max — shared win on a tie); `playCard(state: GameState, seat: SeatId, value: number, target: CellId): EngineResult`.

`playCard` validates, in order: `seat === state.activeSeat` (else `err('NOT_YOUR_TURN', ...)`); `value` is in `state.players[seat].hand` (else `err('CARD_NOT_IN_HAND', ...)`); `isLegalPlacement(state, value, target)` (else `err('ILLEGAL_PLACEMENT', ...)`). On success: clone state, remove `value` from hand, set `cells[target] = { value, owner: seat }`, `pushLog`; call `resolveChain(state, seat, directionFor(deckId, value))`, apply its `pawnCell` and add `pointsScored` to `players[seat].score`; if `players[seat].deck.length > 0`, draw one card into hand; if `isGameOver(newState)`, compute final scores (adding the visible-card bonus on top of each seat's accumulated `score`), set `players[*].score` to the final totals, set `winner = determineWinners(finalScores)`, set `phase = 'ended'`; else advance `activeSeat` to the next seat in `state.seats` (wrapping around). Return `ok(newState)`.
